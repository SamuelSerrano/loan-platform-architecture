# Component Catalog

## 1. Purpose and authority

This document is the canonical logical component catalog for the Loan Onboarding Platform. It decomposes the containers in the [Container Architecture](CONTAINER_DIAGRAM.md) into cohesive responsibilities and records their interfaces, data ownership, dependencies, architectural confidence, and delivery lifecycle.

The [System Context](SYSTEM_CONTEXT.md) owns actors, external systems, and trust boundaries. Domain catalogs own bounded-context semantics, rules, and event names. Future service specifications may refine internal implementation, but they must preserve the boundaries here or record an approved architecture decision. This catalog defines no source-code classes, executable contracts, schemas, or deployment resources.

## 2. Catalog conventions

### 2.1 Lifecycle dimensions

Design and delivery are independent:

| Dimension | Values | Meaning |
| --- | --- | --- |
| Design status | `Confirmed`, `Derived`, `Proposed`, `Deferred` | Confidence and approval of the logical responsibility. |
| Delivery status | `Planned`, `Specified`, `Implemented`, `Deployed` | Progress from intent to running software. |

Every runtime component is `Planned`. A documented responsibility is not an executable specification and does not imply implementation or deployment.

### 2.2 Interface classification

- **Command:** rejectable intent handled by the authoritative owner. It cannot mutate another context's data directly.
- **Query:** read through an owner-controlled API or an explicitly non-authoritative read model. Entries identify authoritative versus eventually consistent results. No query reads another service's store.
- **Domain event:** completed private fact within the owning bounded context. Domain events are never sent directly through EventBridge.
- **Integration event:** versioned public fact mapped from owned state, minimized for consumers, and delivered asynchronously. It may trigger a consumer command or projection update but never transfers ownership.

Names below reference the existing [Event Storming model](../domain/EVENT_STORMING.md) and [event catalog](../domain/DOMAIN_EVENTS.md). They are documentation references, not competing contracts.

## 10. Execution-profile implications

### Local — Zero AWS Cost

No AWS account or credentials are required. Local adapters remain scoped to the same owner as their hosted equivalents; local files/stores do not become a shared database. Local transport preserves integration-event mapping, at-least-once delivery assumptions, Inbox/Outbox idempotency, retry, DLQ, and recovery semantics.

### AWS Demo — Ephemeral and Free-Tier-Aware

The first deployment remains limited to the walking skeleton. Each deployed service receives owner-scoped DynamoDB persistence and credentials; optional protected objects are introduced only when the slice requires them. No persistent-cost infrastructure is authorized. Retention and teardown remain explicit, and every component in this catalog remains `Planned` until separate evidence supports a later delivery status. See the [cost model](CONTAINER_DIAGRAM.md#7-cost-model-and-governance).

## 11. Boundary invariants

1. A component may change authoritative business data only through an owner command and owner transaction.
2. Queries use an owner-controlled API or a labelled non-authoritative projection; no cross-service database reads exist.
3. Cross-context transactions do not exist. A producer commits its aggregate and Outbox locally; consumers commit their own state and Inbox locally.
4. Domain events remain internal. Public integration events are explicitly mapped, minimized, versioned, and asynchronous.
5. Provider and AWS adapters depend on application/domain ports; domain behavior never depends on their SDKs or DTOs.
6. Public schemas and generated transport types may eventually live in `loan-platform-contracts`; shared domain entities and shared persistence models are prohibited.
7. Caches and projections are disposable and non-authoritative unless the [Data Ownership](DATA_OWNERSHIP.md) catalog explicitly says otherwise.
